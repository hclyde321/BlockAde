# BlockAde 區段學習系統

此公開版本僅提供程式碼，課表為空白示範，PBL 教案未附。錄音、講義、題庫、模型與個人學習紀錄需自行準備；依賴本機教材的測試會略過。此版本尚未完成完整端到端驗證。

本專案提供一個可在同一台電腦啟動的 MVP Web App：本機轉錄課堂錄音、同步反白逐字稿，並在講完相關內容後暫停出題。支援手動輸入逐字稿/題目，以及不需 API key 的本機文字對位。OpenAI 題目對位是選用功能。

目前的產品需求、技術架構與開發順序見 [PRODUCT_PLAN.md](PRODUCT_PLAN.md)。

錄音、題庫 PDF、模型權重、資料庫及密鑰屬於本機資料，已列入 `.gitignore`，不應加入 Git。

## 本機啟動

在 Mac 上可直接雙擊 [啟動醫學App.command](啟動醫學App.command)。它會啟動本機服務並用預設瀏覽器開啟 App；使用期間請保持開啟的終端機視窗。若服務已在執行，雙擊只會打開網頁。

需要 Python 3.12 以上、`ffmpeg`、`ffprobe`、`whisper-cli`、PyMuPDF 與 OpenCC。本機工具可放在 `.tools/bin/`；啟動捷徑會優先使用，直接啟動 Python 時也會在 PATH 找不到工具時搜尋該目錄。API 與前端使用 Python 標準函式庫，不需要安裝 FastAPI、uvicorn 或 npm 套件。Python 套件可用專案 requirements 安裝：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python3 server.py
```

開啟 <http://127.0.0.1:8000>。服務只綁定本機回環位址。逐字稿模型預設讀取未量化 FP16 的 `models/ggml-large-v3.bin`，也可設定 `WHISPER_MODEL` 指向其他 GGML 模型（不能直接使用 `.pt`）。缺少模型時會報錯，不會自動退回 Q5。若 Metal 無法啟動，轉錄會自動改用 CPU 重試一次；也可用 `WHISPER_NO_GPU=1 python3 server.py` 強制使用 CPU。轉錄受 `WHISPER_TIMEOUT_SECONDS` 限制，且同時只處理一堂課。

### 保留原話的轉錄設定

- 中文轉錄，保留英文詞彙，不啟用翻譯；beam size 5、best-of 5，從 temperature 0 開始，解碼失敗時以 0.2 逐次升溫重試。預設 8 執行緒，CPU 重試沿用同一組設定。
- 不加 VAD 裁切、額外 token suppression、去重、潤稿或自動補字。仍保留 Whisper 原有的無語音判斷，以免靜音產生幻覺；這也表示小聲語音仍可能漏掉。
- 輸出僅以 OpenCC `s2t` 轉繁體，不使用 `s2twp` 的台灣用語替換（例如保留「軟件」，不改為「軟體」）。辨識到的語助詞、重複和口誤不刪除。
- `WHISPER_PROMPT` 可選填與錄音相關的短詞表，例如 `ECG, electrocardiogram, troponin`。預設留空，不塞入虛構口語範例或指令，避免提示污染。提示不保證模型遵守。
- 每次成功轉錄會在 `data/transcription_raw/<隨機識別碼>.json` 保留模型原始 JSON、使用的模型與解碼設定、音訊來源和初稿。檔案不會因後續文字編輯而改變，且不納入 Git。
- 原始 JSON 內時間戳相對於各片段；加上 `raw_outputs[].audio_start_ms` 與 `source_offset_ms` 即對應原始錄音。`segments` 時間戳相對於所轉錄範圍，加上 `source_offset_ms` 即是完整錄音時間。分段合併沿用 2 秒重疊和依段落中點歸屬的策略，交界處仍應重聽校對。
- 模型可能省略語助詞或聽錯，即使 FP16 也不能保證真正每字正確。可點段落時間戳重聽、編輯文字，並使用既有的局部重新辨識功能；藥名、劑量、數字與否定詞尤其需要校對。

切換模型只影響之後的新轉錄／重新辨識，不會自動覆寫既有課程逐字稿。已啟動的服務需重新啟動才能載入程式修改。

模型轉換工具是 `maintenance/convert_large_v3.py`（額外需要 NumPy，只在轉換時使用）。它僅接受已核對 SHA-256 的官方 `large-v3.pt`，限制反序列化類型並處理原始權重的 tensor strides，輸出後再比對 whisper.cpp 發布的 FP16 模型 SHA-256。使用官方 Whisper repository 的 `whisper/assets` 作為第二個參數：

```bash
python3 maintenance/convert_large_v3.py ~/.cache/whisper/large-v3.pt /path/to/whisper/whisper/assets models/ggml-large-v3.bin
```

## 科目、題庫與新錄音

「我的課程」依病理學、藥理學、臨床醫學、檢驗醫學分組。既有課程與題庫會自動歸入臨床醫學。

1. 在科目的題庫管理建立具名題庫，分別上傳題目 PDF 與答案解析 PDF，再匯入。每科可有多份題庫。
2. 在科目下建立一堂課，可選擇每 **5 分鐘（預設）** 或 **10 分鐘** 獨立轉錄。上傳前也能在課程頁調整；只要上傳錄音，就會自動排入本機轉錄，接著比對該科所有已匯入題庫。不需要每堂課重傳 PDF；沒有題庫也能先轉錄。
   - 分段結果會合併為整堂課的逐字稿，保留原錄音的時間位置；分段可限制重複錯誤延伸，但不能保證辨識完全正確。
   - 已有錄音可調整設定後按「重新轉錄」；全部成功後才更新自動逐字稿，作答紀錄保留。含人工修改的逐字稿仍受保護，不會被重新轉錄覆蓋。
3. 轉錄進度取自 Whisper 回報的百分比或已處理音訊時間；模型載入時可能暫停在同一數字，不以計時器假裝進度。GPU 失敗改用 CPU 時會顯示重試，百分比可重新開始。轉錄後另有題目比對階段。
4. 新增題庫後，選取既有課程重新比對。已存在題目及作答紀錄會保留，新增題庫的題目會補入。

每堂課的題目與作答獨立。已匯入題庫不可直接覆寫，以免破壞學習紀錄；有新版時新增另一份具名題庫。新一堂錄音也請建立新課程。

## 學習輪次與錯題複習

實際播放的片段會累計為聽課進度，重複聽同一片段不會重複增加百分比，拖曳跳過的片段不計入。聽過至少 90% 算完成一輪。播放位置、完成輪數會保存；「重新學習」建立新輪次，重新出題，歷次作答仍保留。

錯題複習可依科目、課程篩選。最近一次答錯的題目出現在待複習清單；答對後移出，再答錯時重新加入。曾經答錯的題目仍可在歷史清單查看。作答後立即顯示答案與解析。

錄音、PDF、SQLite 資料庫及轉錄工作檔放在忽略的 `data/` 目錄。上傳限制為錄音 750 MB、每份 PDF 50 MB。模型尚未就緒時，仍可手動輸入逐字稿與題目。本機文字對位只會為文字證據明確、題幹與答案可用的題目設定自動出題時間；證據不足時保留「未配對」，播放時不會跳出。可在課程頁重新執行本機對位，不需要 OpenAI API key。

本機對位會分析該課所有題目，只以題幹和逐字稿的文字作保守比對。它能處理部分繁簡字差異，但無法可靠理解同義改寫或判斷醫學語意；可在「未配對」清單手動設定確實相關的出題時間。已作答紀錄會保留。對應 API 為 `POST /api/courses/{id}/rematch`。

### 選擇性 OpenAI 題目對位

課程頁每次最多分析 20 道候選題；先以本機文字篩選，再由 OpenAI 驗證講課證據，無關題目不設定時間。已儲存的 OpenAI 結果會保留，重試或再次分析接續其他題目。短暫速率限制會顯示等待狀態並有限次重試；額度與花費上限錯誤不會自動重試。

題幹與選項可讀時，即使答案尚未完成校對，仍可分析相關逐字稿並顯示建議時間。只有答案有效、題目已完成校對且講課證據明確時才會自動確認出題。分析摘要會列出實際送出題數、已確認／待確認時間，以及略過原因；有本機候選不代表已經確認相關。

只有在課程頁明確按下「使用 OpenAI 分析題目對位」後，服務才會呼叫 Responses API。每題最多送出 3 個本機篩選的逐字稿候選窗、合計最多 8,000 個逐字稿字元，以及該題的題幹、選項、正解與精簡解析；不會上傳錄音檔或 PDF 檔。請先確認這些文字可以送往 OpenAI。請勿把 API key 貼到聊天、寫入程式碼或提交到 Git。

可直接在課程頁按「OpenAI 設定」，輸入 API 金鑰與模型名稱後儲存，再按「OpenAI 深度分析」。金鑰只保留在本機服務記憶體，不寫入檔案、瀏覽器儲存或 Git；重啟服務後需重新輸入。「清除」只會移除本次服務設定，若原本設定了環境變數仍會使用它。儲存只檢查格式，不代表金鑰、額度或模型權限已通過 OpenAI 驗證；實際分析時才會連線並可能產生費用。

也可以在 zsh 終端機中以隱藏輸入設定 key，再從同一個終端機啟動服務：

```sh
read -s "OPENAI_API_KEY?OpenAI API key（輸入不會顯示）: "
printf '\n'
export OPENAI_API_KEY
export OPENAI_MATCH_MODEL=gpt-6-sol
python3 server.py
```

Key 只留在目前終端機的環境中，服務不會寫入 key 或完整請求內容。若沒有設定 key，分析 API 會顯示可操作錯誤；手動校對仍可使用。Responses request 設定 `store: false`，但這不取代你對所用 OpenAI 帳戶與資料處理方式的確認。

後端端點：

- `POST /api/courses/{id}/analyze-matches`，可傳 `{ "max_questions": 40 }`（最多 100）；回 `{ "job": ... }`。
- `GET /api/courses/{id}/job`，輪詢 `match_analysis` 工作的 `status`、`stage`、`progress`、`message` 與 `error`。
- 高信心結果只有在證據段落 ID、題目答案與選項都能由本機資料驗證時才會自動確認；其他候選仍待人工確認。沒有達本機候選門檻的題目不會送出。

PDF 解析器已使用提供的 B11 臨床醫學 Block 1 題目與答案 PDF 完整驗證；其他課程版型、掃描 PDF、圖片題或特殊多選答案仍可能需要人工校對。如需單獨安裝 PDF parser，可執行 `python -m pip install PyMuPDF`；套件清單在 [requirements.txt](requirements.txt)。

## 持續學習 API

- `GET /api/subjects`：四個固定科目。
- `GET/POST /api/banks`：列出或建立具名題庫；`subject_id` 可篩選科目。
- `PUT /api/banks/{id}/assets/questions`、`.../answers`：上傳 PDF；`POST /api/banks/{id}/import` 匯入。
- `PATCH /api/courses/{id}/transcription-settings`：儲存 `transcription_chunk_minutes`（整數 5 或 10）；課程處理中不可修改。建立課程也可傳入同名欄位。
- `PUT /api/courses/{id}/assets/audio`：上傳錄音並自動排入轉錄；以 `GET /api/courses/{id}/job` 查進度。
- `POST /api/courses/{id}/rematch`：補入該科新題庫並重新比對，保留已存在題目與作答。
- `POST /api/courses/{id}/listening`：回報連續聽過的區間與 `round_id`；播放器會排除跳播。
- `POST /api/courses/{id}/restart`、`GET /api/courses/{id}/history`：開始新輪次與查看歷史。
- `GET /api/wrong-questions`：可帶 `subject_id`、`course_id`、`history=1` 查曾答錯題目。


## 編輯課程與局部重新辨識

- 課程頁的「編輯名稱」可更新名稱，課程內容、學習進度與作答紀錄保留。
- 已有錄音的課程可選「局部重新辨識」，輸入開始／結束時間（例如 `26:06` 到 `30:00`，也支援 `01:02:03`）。使用該課的 5／10 分鐘設定在本機處理。
- 選取範圍若切到既有字幕句子中間，處理範圍會延伸至完整段落邊界，工作訊息會顯示實際範圍。含人工修改段落時會拒絕覆蓋。
- 成功後只替換該範圍逐字稿，更新本機題目比對；其他段落及作答紀錄保留。轉錄失敗時原稿不變。
- `PATCH /api/courses/{id}`：`{"title":"新名稱"}`。
- `POST /api/courses/{id}/retranscribe-range`：`{"start_seconds":1566,"end_seconds":1800}`，回傳背景工作，以既有 job API 查進度。


## 每段完成即顯示逐字稿

- 每完成一個 5／10 分鐘區段，課程頁自動顯示該段的唯讀逐字稿預覽，可點時間跳到錄音位置；後面的區段仍繼續辨識。
- 預覽顯示完成段數，重新開啟課程仍可查看。後續辨識失敗時，已完成內容保留並標示為未完成。
- 全堂或局部重新辨識期間，預覽與既有正式逐字稿分開顯示。全部成功後才更新正式逐字稿與題目配對，避免半成品覆蓋原稿。
- 此功能需要啟動新版後端；已經在舊版開始的轉錄工作仍使用原本流程。

### 題目分析分類

課程題目可依「尚未分析」「已配對時間」「非本堂課」「待確認」切換並查看數量。僅本機找不到候選不等於 OpenAI 已判定無關；這些題目仍屬尚未分析。「非本堂課」代表 OpenAI 依目前提供的講課證據判定未配對，並非保證整份錄音絕無相關內容。「待確認」保留模型不確定或題目資料需校對的結果。在尚未分析分類按繼續分析，每次最多驗證 20 題；已保存的 OpenAI 結果不會重複送出。

### 全螢幕逐字稿

課堂逐字稿右上角提供全螢幕閱讀入口，預設將逐字稿放大至 22px，並提供 A−／A＋字級調整，保留原本的播放器、反白與跟隨捲動。可用退出按鈕或 Escape 回到課程畫面；瀏覽器不支援原生全螢幕時仍可使用填滿網頁的閱讀模式。

## 課程講義輔助比對

在課程的「上課講義」區塊可上傳多份可選取文字的 PDF（每份最多 50 MB、500 頁），與題庫、答案解析分開管理。掃描講義需先完成 OCR；目前不直接支援 PPT。

上傳後按「繼續分析尚未分析題目」，本機先搜尋題目相關的講義章節／頁面文字，再讓 OpenAI 參考相關講義片段與逐字稿候選。講義頁碼不會當成錄音時間；只有逐字稿證據足夠時才指定出題時間。講義相關但沒有時間證據的題目列為待確認。文字搜尋仍可能漏掉跨語言或不同用語的內容，並非保證找出所有相關題目。

新增或移除講義會清除本課程先前 OpenAI 的無關／待確認結果及講義本機待確認結果，讓它們可以重新分析；保留已確認時間與作答紀錄。上傳本身不會呼叫付費 API，明確按下分析後才會傳送相關文字。分析摘要顯示的是本輪結果；略過的題目不代表已完成分析。

## 同一堂課的多份錄音

在課程錄音區選取多個檔案，先於待上傳清單調整上下順序，再開始上傳（每堂最多 32 段、每檔最多 750 MB）。檔案會依清單順序加入同一堂課，完成上傳後自動合併並以本機 Whisper 轉錄。之後可追加新的錄音；新錄音接在既有錄音後面，逐字稿與題目沿用整堂課的連續時間軸。

追加錄音會保留既有逐字稿、已確認題目時間與作答紀錄。尚未確認或先前判定無關的結果可重新分析，因為課程增加了新內容。課程進度依延長後的總長度重新計算。已上傳的錄音順序固定；請在送出前確認排序。

若某個檔案上傳失敗，先前成功上傳的檔案會留在課程中；合併或轉錄失敗可重試處理已上傳錄音，不必重傳成功的檔案。合併與新增逐字稿一起成功後才會取代原播放音檔，以避免失敗重試造成重複追加。

### 疑難短段第二輪與字幕匯出

每次主辨識後，檢查低 token 分數（平均 < 0.65 或任一文字 token < 0.25，非校準正確率）、相鄰重複、分段交界、10 秒以上無文字區間與異常時間戳。疑點不直接代表錯誤；靜音與講者真正重複都會留下原稿。

預設自動挑最多 3 個不重疊的約 30 秒片段，以同一 Large v3、beam 8、temperature 0、無升溫做第二輪比對；没有疑點時抽查一段。每段辨識最多 180 秒，失敗不丟棄主稿。`WHISPER_REVIEW_LIMIT` 可設 0–12（0 關閉自動複核）。兩輪文字保留供人工核對，不自動採用第二輪、不根據講義補話。完整錄音不會每次重跑兩輪。

「辨識複核／字幕」顯示最近一次辨識範圍（整堂、新增部分或局部），可重聽、選取片段重新辨識、下載原始 TXT/VTT/SRT/JSON。字幕用模型時間加上切片起點，保留靜音間隔，不強制第一句從零開始或最後一句延長到音檔結束。這些是辨識初稿；原本的「下載逐字稿」則匯出目前可編輯的逐字稿。

不會自動強力降噪；保留上傳的原始錄音。現有流程仍混合成單聲道，若左右聲道品質差距很大，應先另製作選定聲道版本上傳。

### 本地醫學校訂、修訂紀錄與重新對齊

課堂逐字稿的「醫學校訂」按鈕提供每次五分鐘的校訂流程：選取區間、輸入術語背景（選填）、產生建議、重聽並逐項採用／略過，最後對齊此區間的校訂文字。既有逐字稿也可直接使用，不必重跑整堂辨識。每段每輪最多三個互不重疊的短詞建議，合併為一筆修訂；不保證能發現所有錯字。採用後仍標示「推定校訂，待聽核」，不把語境推測當成確認原話。

文字建議使用獨立的本地 Qwen3 4-bit 模型（8B、30B-A3B 或 Qwen3.6-35B-A3B）（這不是錄音模型；錄音仍用完整未量化 Large v3）。課程名稱、前後文與選填術語只作候選字詞參考，不會上傳至 OpenAI 或其他服務。只允許原文中唯一出現的有限長度短詞替換；舊建議若原段落已變動便不能採用。模型不是醫學事實或錄音原話的裁判，不能根據建議更改醫療決策。

新版本地校訂每批處理最多 60 秒／24 段，參考前後各約 90 秒的課堂文字（可跨越五分鐘區間）。程式從這堂課已上傳講義與使用者背景中擷取英文詞彙，按與原辨識詞的字形相近程度選取最多 100 個拼字參考，不把講義句子補進逐字稿。同一本地模型先提出候選，再以新的審核提示選擇保留項目；這不是獨立模型共識，也沒有直接聽音訊。程式額外攔截跨語言翻譯、句子改寫、數字與否定詞變動、純大小寫／空白調整。唯一的跨語言例外是最多八字的中文音似誤辨：附近短段重辨識也必須出現候選英文，才可提出恢復英文術語的推定，仍需人工聽核。同輪及先前採用的短詞對應供一致性參考，矛盾候選不保存。每項建議仍須聽核，不會自動套用；不能保證與 Sol 稿等品質。

有錄音時，校訂前會先把每批音訊（前後最多各兩秒、總長上限 90 秒）以 Large v3、beam 8、temperature 0、無提示詞重新辨識，再把這份結果交給文字模型一起比較。候選詞不會傳給 Whisper。原音重辨識的文字與時間隨建議存入校訂紀錄，介面顯示附近三秒範圍是否出現同一候選拼字；這只表示辨識文字相符，不能視為原音已驗證。若短段重辨識失敗，會明確標示僅參考文字語境；不覆蓋既有逐字稿。

每個五分鐘校訂工作也會先依本堂課區間和前後文，由同一本地模型整理最多 80 個推定術語。輸出若達長度上限，僅保留完整的 JSON 字串詞條，截斷的詞不使用並註明限制。模型推定詞彙與講義詞彙分別記錄來源，都是拼字候選；前者不能充當講義或原音證據。若術語表產生失敗，會在建議紀錄註明，既有文字／講義校訂仍可繼續。相同原文與候選文字的待採用建議，不因背景或重聽資訊變動而重複新增。

可安裝較大的本地文字校訂模型：`.venv/bin/python maintenance/setup_medical_models.py --profile 30b`。使用 `mlx-community/Qwen3-30B-A3B-Instruct-2507-4bit`，固定 revision `e9675aa3ca5f900ccef55267914466d55ab325fa`，約 17.2 GB。亦可用 `--profile 35b` 安裝 `mlx-community/Qwen3.6-35B-A3B-4bit`（revision `38740b847e4cb78f352aba30aa41c76e08e6eb46`，約 20.4 GB）。下載完成並校驗後，重新啟動 App 按 35B、30B、8B 的順序選擇已安裝模型。可用環境變數 `MEDICAL_REVIEW_MODEL=8b`、`30b` 或 `35b` 明確選擇，介面和每項紀錄都顯示實際模型。這些都是本地文字模型的 4-bit 版本；語音模型仍是完整未量化 Large v3。Whisper 與文字模型依序執行，降低記憶體重疊。35B 以非思考模式、temperature 0.7、top-p 0.8、top-k 20、presence penalty 1.5、固定 seed 42 生成，依模型官方設定避免貪婪解碼的重複；這些是文字模型參數，Whisper 重辨識仍從 temperature 0 開始。35B 每批目標上限 16 段，以簡短代號對應原段落 ID，避免模型抄錯長 ID。

採用建議、手動編輯、成功／失敗的重新對齊都保存到 SQLite 的 `transcript_revisions`，含修改前後文字和時間、理由、模型、採用狀態與日期。介面可下載 JSON 紀錄。原始 Whisper 存檔不變；推定標記在後續對齊及手動編輯後仍保守保留。若需要撤回採用，可依紀錄手動改回原文，此操作也會另存紀錄。

對齊採 stable-ts 2.19.1 與既有 `~/.cache/whisper/large-v3.pt` 官方權重，於 CPU 上執行，沒有再次下載 Whisper 或使用雲端 ASR。一次處理所選五分鐘內已採用建議或手動編輯的段落；單一段落上限 60 秒。各段擷取前後最多兩秒、受相鄰段落限制的原始音訊，計算詞時間，不使用字數平均分配。缺字、零長度、倒退、重疊或過期結果都不套用，失敗理由留存。對齊是估計時間，不證明推定字詞正確；單段可能耗時數分鐘。

閱讀畫面與「下載逐字稿」TXT 每五分鐘一個區間標題（00:00、05:00…），按段落起點歸入區間，跨界句不切字、沒有文字的區間不捏造內容。每句的重聽與同步反白仍用原有細部時間；原始 VTT/SRT 仍保留字幕所需的逐句時間。

首次在 Apple Silicon 電腦安裝（需網路；約 4.6 GB 校訂模型加套件）：

```sh
.venv/bin/python -m pip install -r requirements-local-review.txt
.venv/bin/python maintenance/setup_medical_models.py
```

模型固定到 `mlx-community/Qwen3-8B-4bit` revision `545dc4251c05440727734bcd94334791f6ab0192`，下載器驗證檔案大小與 LFS SHA-256 後才發布檔案。權重放在已排除 Git 的 `models/medical-qwen3-8b/`。執行校訂時設 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`，模型從本地路徑載入，沒有雲端後備。若缺套件或模型，介面會停用對應按鈕。新增功能不需要 API key，也不計 OpenAI API token 費用。

參考：[MLX LM](https://github.com/ml-explore/mlx-lm)、[Qwen3 模型](https://huggingface.co/mlx-community/Qwen3-8B-4bit)、[stable-ts 對齊文件](https://github.com/jianfch/stable-ts#alignment)。stable-ts 上游已暫停開發，因此固定版本並以實際音訊驗證相容性。

實際中英混合錄音測試補充：中文對齊器可能把英文單詞拆成子詞，單一字母的時間長度可能為零。程式先把沒有空白分隔、時間順序正常的拉丁字母子詞合回英文詞，再處理零長度標點；整個詞都沒有時間、中文零長度單位或倒退時間仍會拒絕。重試對齊時會略過文字與時間均未再變動的成功段落，只處理尚未成功或再次修改的段落。

校訂介面預設只列出所選五分鐘區間的待採用建議；「全部校訂紀錄」與 JSON 匯出保留歷史。完整候選、第二輪審核、詞彙來源與重辨識參考另存於本機 `data/medical_review_runs/<job_id>/`，不納入 Git。

校訂模型回傳無效 JSON 時，會以更明確的格式要求在本機重新生成，最多三次；不猜補缺損的候選文字。成功重試後，原始格式錯誤輸出也隨該批審核紀錄留存。連續失敗會顯示工作未完成，保留原稿與先前已產生的建議。

文字模型資料：[Qwen3.6-35B-A3B 官方模型卡](https://huggingface.co/Qwen/Qwen3.6-35B-A3B)。

## 極簡 UI 與 PBL 畫面

主選單為課程、PBL、題庫、錯題。課程首頁改為單行清單；課程內容以逐字稿、講義、題目分頁顯示，次要控制收進「更多」。校訂一次顯示一項，其餘來源與紀錄可展開查看。

PBL 已提供第 1–16 週教案瀏覽、本機關鍵字配對與 OpenAI API 配對。進入週次後勾選科目，點「API 設定」輸入金鑰與支援 Responses／Structured Outputs 的模型，再按「API 配對」。設定與題庫共用；金鑰僅在服務記憶體中，重啟後須重新輸入（或使用既有環境變數）。目前只接 OpenAI 官方端點，不提供自訂相容端點。

每次 API 配對只分析目前週次和所選科目，會送出教案文字與每堂課最多四個本機篩選的逐字稿片段（各最多 1,600 字、總計上限 100,000 字）；不送錄音或 PDF。教案上限 30,000 字，超限會提示縮小範圍。這是候選片段分析，未列出不代表整堂課完全無關。模型須引用實際提供的課程及段落 ID；文字和時間由本機段落取回，無效回應不覆蓋舊結果。只有點擊 API 配對才呼叫付費 API；本機配對不使用 API。

API 結果保存在 SQLite 的 pbl_api_results，依週次儲存最近一次成功結果，重整後可讀取；同週重新分析會取代該週 API 結果。教案仍讀取本機 web/pbl-materials/search.json，換電腦需另行還原此資料夾。通用教案上傳尚未實作。API 請求最多等待 120 秒；失敗不自動重試，以免重複付費。
